# Selfvoy — отчёт о работе (11–13 октября 2026)

Состояние ветки `main` на момент сборки архива: коммит указан в имени архива.
Ниже — что сделано и исправлено, как это проверено и что стоит доработать.

## 1. Что сделано

### 1.1 Дизайн всех клиентов (редизайн v3)
- Desktop (Qt6/QML), Android (Compose), iOS (SwiftUI) приведены к макетам v3:
  тёмная палитра `#0B0C10 / #12141C`, тонкие рамки, без неона.
- Парящая «стеклянная» панель вкладок на телефонах, стеклянные пузыри чата.
- Исправления по скриншотам с устройств: панель вкладок на Android, подсказки за
  краем экрана на iOS, иконки приложения (iOS, Windows), короткие реплики чата
  в одну строку на десктопе, карточка контакта за краем окна и др.

### 1.2 Веб-клиент (`web/`: браузер, Android APK через Capacitor, Windows EXE через Electron)
- Демо на моках заменено настоящим клиентом протокола Selfvoy:
  WebSocket с таймаутами, переподключением и перебором адресов; экран
  «Сервер Selfvoy не отвечает» с «Повторить» вместо белого экрана.
- Регистрация, код из письма, вход, 2FA TOTP (QR, ключ, 10 резервных кодов,
  доверенные устройства на 90 дней), восстановление пароля, refresh-токены.
- Настройки: профиль (аватар, имя, «о себе»), предпочтения (питание, бюджет…),
  «Приватность ИИ» (три переключателя), смена пароля, активные сессии.
- Переговоры Аур — карточка итога и короткий таймлайн шагов.
- Адрес сервера: `.env` (`VITE_SELFVOY_SERVER_URL`, `VITE_SELFVOY_FALLBACK_URL`),
  переменная CI `SELFVOY_SERVER_URL`, ввод в приложении; Android-эмулятор —
  `10.0.2.2`.
- Сетевые политики: Android cleartext/mixed content для локальной сети, iOS ATS,
  Content-Security-Policy в сборке.
- **Админ-панель** (`/admin`, см. 1.5).

### 1.3 Сервер и AI: новые возможности
- `profile.update` (имя, «о себе», аватар) и `prefs.privacy` — сервер сам
  применяет приватность в переговорах (что видит чужой Selfvoy, названия событий,
  выбор места).
- **Почта: коды подтверждения и сброса уходят настоящими письмами по SMTP**
  (`SELFVOY_MAIL_DRIVER=smtp`, STARTTLS/SSL через OpenSSL, проверка сертификата,
  текст + HTML). Проверено на тестовом SMTP со STARTTLS и авторизацией.
- Нативные клиенты (Android, iOS, Qt) получили редактирование профиля и
  «Приватность ИИ».

### 1.4 Аудит безопасности и багов — что найдено и исправлено
Аудит провели три независимых проверяющих (сервер, AI+инфраструктура, веб);
большинство проблем воспроизведено на работающем сервере до исправления.

**Критичные**
| Проблема | Исправление |
|---|---|
| Сервер по умолчанию в dev-режиме почты: `auth.forgotPassword` возвращал код сброса прямо в ответе — любой мог сменить пароль любого аккаунта | по умолчанию `log`; `dev` только с `SELFVOY_DEV_MODE=1`, иначе сервер не стартует |
| Токен проверялся по сессии, но пользователь брался из `sub` без сверки; секрет по умолчанию `selfvoy-dev-secret` — поддельный JWT = вход под любым аккаунтом | сверка владельца сессии; без сильных `SELFVOY_JWT_SECRET` и `SELFVOY_2FA_KEY` сервер не стартует |
| docker-compose монтировал `seed.sql` с демо-аккаунтами (пароль известен) в рабочую БД | в БД при инициализации только `schema.sql` |

**Высокие**
- Разбор JSON за O(n²): один кадр до входа грузил ядро ~20 с → линейный разбор, ≤1000 ключей, кадр до входа ≤64 КБ.
- Argon2 по 64 МБ без ограничений → OOM → семафор по числу ядер, проверка занятого email до хэширования, лимит регистраций.
- Код из письма перебирался за ~2 минуты; TOTP перебирался без лимита (верный пароль сбрасывал счётчик; лимит по `ip:порт`) → 5 попыток на код, отдельный счётчик 2FA, лимиты по IP без порта. Код сброса — теперь 6 цифр с тем же ограничением.
- Повторный `setup2fa` молча выключал 2FA → отказ, если 2FA включена.
- Отзыв сессий / смена пароля не закрывали уже открытые соединения → соединения закрываются (событие `session.revoked`), плюс перепроверка раз в 15 с.
- `agent.ask` читал чужие чаты и данные других людей → только свои чаты, данные собеседников — с учётом их приватности.
- AI-сервис и PostgreSQL были открыты наружу, AI работал без токена (читалась/писалась чужая память) → порты не публикуются, без `SELFVOY_AI_TOKEN` AI отвечает 503, отдельные роли БД вместо суперпользователя.
- Веб: токены могли уйти на запасной `ws://` без шифрования; в Electron перетащенный HTML-файл получал доступ к токенам; 2FA обходилась через общий id устройства `web-ephemeral` → всё закрыто.

**Средние и низкие (выборочно)**
- logout/revoke не отзывали refresh-токены; `users.search` выдавал email всех пользователей; подмена сообщений «от Selfvoy» через `chat.send`; внедрение заголовков в письма `send_email`; рассылка писем на чужой адрес без лимита; лимит соединений на IP; переподключение к PostgreSQL; отключённый пользователь сохранял доступ; `tool.run` обходил разрешения; гонки двойного подтверждения и refresh; SQL-ошибки и текст исключений в ответах; повреждённая встроенная БД молча заменялась пустой; секрет AI уходил во внешние API.
- AI: инструменты с внешним эффектом исполнялись самим AI (теперь только сервер, после проверки прав); ответ LLM не проверялся; 500 на некорректный ввод; блокировка event loop в распознавании речи; неатомарная запись памяти; `/healthz` раскрывал строку подключения к БД.
- CI: публикация сборок из любой ветки, токен с правом записи у сборок с внешними зависимостями → публикация только из `main`, токен только на чтение для сборок.
- Веб: гонка refresh в двух вкладках выкидывала со всех устройств; вечный спиннер без сервера; выход без сети ждал 25 с; данные оставались после выхода; Android-бэкап уносил токены; ошибки отзыва сессий выдавались за успех; чужие сообщения при переключении чатов и др.

**Баги, найденные попутно**
- Сервер не отвечал на запросы с числовым `id` (терялся ответ).
- После первого напоминания переставали работать переговоры (AI отвечал 422).
- «Напомни завтра в 10 позвонить юристу» превращалось в задачу с этим текстом на полночь UTC → «Позвонить юристу», завтра 10:00 по часовому поясу пользователя.
- `auth.token` на новом соединении не возвращал пользователя.
- iOS: после прокрутки настроек пропадала кнопка «Назад» (и падал UI-тест).
- `auth.verifyEmail` для уже подтверждённого адреса отдавал данные пользователя без кода.

### 1.5 Админ-панель (роли и модерация)
- Роли `user` / `moderator` / `admin`; первые админы — `SELFVOY_ADMIN_EMAILS`
  (только подтверждённые адреса).
- Обзор (пользователи, онлайн, сессии, 2FA, блокировки), список пользователей
  (поиск, фильтры), карточка: блокировка с причиной (сразу выход со всех
  устройств), завершение сессий, смена роли (только админ), журнал аудита
  (только админ). Модератор управляет только обычными пользователями.
- Проверено вживую в браузере против сервера.

## 3. Перед выкатом (обязательно)
1. **Миграции БД** на существующей базе:
   `schema/migrations/2026_10_13_privacy.sql` и `2026_10_13_roles.sql`
   (без второй сервер на PostgreSQL не найдёт пользователей). На уже
   существующем томе PostgreSQL создать роли `selfvoy_app`/`selfvoy_ai` вручную
   (`deploy/postgres/20-app-roles.sh`, см. `docs/SETUP.md`).
2. **`.env`** (шаблон `.env.example`): `SELFVOY_JWT_SECRET`, `SELFVOY_2FA_KEY`,
   `SELFVOY_AI_TOKEN`, пароли БД — сгенерировать (`openssl rand -hex 32`);
   `SELFVOY_ADMIN_EMAILS`; почта `SELFVOY_MAIL_DRIVER=smtp` + `SELFVOY_SMTP_*`.
   `SELFVOY_DEV_MODE` и `SELFVOY_AI_INSECURE_DEV` в проде не задавать.
3. **Почтовый домен**: SPF, DKIM, DMARC — иначе письма с кодами уйдут в спам.
4. **TLS**: сервер слушает `ws://` — наружу публиковать только через обратный
   прокси с TLS (`wss://`); за прокси поднять/отключить лимиты по IP
   (все клиенты приходят с одного адреса, см. SETUP).
5. **Сборки клиентов**: задать переменную репозитория `SELFVOY_SERVER_URL=wss://…`,
   чтобы адрес сервера вшивался в APK/EXE.

## 4. Что стоит доработать
**Важно**
- ~~Нативные клиенты не знают о новых возможностях сервера~~ — сделано
  (14.10): `session.revoked`, новая пара токенов после `auth.changePassword`
  (Qt), `users.search` без email (чат по id), `tool.run` с
  `requires_confirmation`; запись и рефералы есть во всех клиентах.
- **Админ-панель только в веб-клиенте** (и в .exe/.apk на его основе); в
  нативных клиентах её нет.
- **Google-интеграции (Календарь/Gmail)**: в сервере нет HTTPS-клиента — нужен
  исходящий TLS-прокси или поддержка TLS в `net.cpp` (сервер предупреждает при
  старте).
- **Push (APNs/FCM)** — только через внешний шлюз (`SELFVOY_PUSH_WEBHOOK_URL`),
  шлюз в репозитории не реализован.
- ~~Счётчики попыток живут в памяти процесса~~ — сделано (14.10): на
  PostgreSQL они общие (таблица `rate_limits`), запись встречи идёт под
  advisory lock'ом владельца; см. SETUP.md → «Несколько экземпляров сервера».
- **Проверить рабочую БД PostgreSQL**: до 14.10 новые аккаунты там создавались
  уже подтверждёнными — `tools/sql/unverified_accounts.sql` находит их и
  (по флагу `-v apply=1`, с перепроверкой под блокировкой) сбрасывает
  подтверждение. Перед сбросом — рабочая почта (`SELFVOY_MAIL_DRIVER=smtp`).

**Желательно**
- Английский язык интерфейса (сейчас только русский) и ответы Selfvoy на языке
  запроса; запасной разбор фраз без LLM понимает только русский.
- Подключить реальную LLM (`SELFVOY_LLM_PROVIDER`); сейчас без ключа работает
  локальная «модель на правилах» с ограниченным пониманием.
- Deep links `selfvoy://` в веб-оболочке (Capacitor) не настроены.
- Токены на телефонах (веб-клиент) — в хранилище WebView; лучше перейти на
  Keystore/Keychain через плагин.
- Сборки Android/iOS не проверены на реальных устройствах в этой работе
  (только эмулятор/симулятор в CI); UI-тест iOS исправлен по анализу кода —
  подтвердить зелёным «Device check».
- Закрепить GitHub Actions по SHA; добавить actionlint и прогон `make e2e` в CI.
- Модерация контента (жалобы, скрытие сообщений) — в админ-панели пока только
  управление пользователями.
