# Протокол Agent-to-Agent (A2A)

Переговоры двух Аур о встрече: инициатор формулирует запрос («хочу
встретиться с Аней в эти выходные»), его Аура обращается к Ауре Ани,
та ищет пересечение свободных слотов и предлагает место.

## Транспорт

Оба агента живут на одном C++-сервере (одна база пользователей) —
«переговоры» это вызов `AgentManager::negotiate` → HTTP
`POST /v1/agent/negotiate` в Python AI Service (заголовок `X-Aura-Token`).
Внешнего федеративного протокола нет: межсерверный A2A — осознанно за
рамками v3 (см. ROADMAP).

## Запрос

```json
{
  "initiator": { "user_key": "...", "memory": [...], "calendar": [...] },
  "responder": { "user_key": "...", "memory": [...], "calendar": [...] },
  "intent": "schedule_meeting",
  "topic": "обсудить стартап",
  "duration_minutes": 60,
  "window_hours": 96
}
```

Контексты (`AgentContext`) собирает C++-сервер из памяти и расписания
обоих пользователей — AI-сервис не имеет доступа к базе и не видит ничего,
кроме присланного контекста.

## Ответ

```json
{
  "accepted": true,
  "slot":  { "start": "2026-09-27T12:00:00", "end": "2026-09-27T13:00:00" },
  "place": { "name": "Кофейня на полпути", "lat": 50.88, "lon": 5.97 },
  "message": "Договорились: суббота, 12:00",
  "counter_slots": []
}
```

Логика (`ai/aura_ai/agent.py`): свободные слоты обоих (планировщик,
до 8 вариантов на сторону, длительность ≥ 15 мин) → пересечение →
если есть общий слот — `accepted` + место между городами/координатами
из памяти; иначе — `counter_slots` (топ-3 слота отвечающего) и
`accepted: false`.

## Как раунды видит пользователь

- Каждый вызов переговоров — один раунд «предложение → ответ».
- Результат публикуруется в чат сообщением `kind=agent_reply`
  (payload: `origin=aura-a2a`, `proposal=…`) — его видят оба участника.
- Отвечающему additionally приходит уведомление `a2a.proposal`
  (этап 13) — даже если клиент закрыт.
- Эскалация: если согласия нет, инициатор получает `counter_slots` и
  решает человек — следующего раунда без его участия не будет.
  Автономной многоходовой переписки агентов нет — это сознательное
  ограничение (правило владельца: пользователь видит каждый раунд).

## Безопасность

- Переговоры не исполняют опасных действий: бронирование столика —
  отдельный инструмент, который проходит барьер подтверждения
  (`pending_actions` → `confirmation.approve`) и проверяется по
  `tool_permissions` отвечающего.
- `agent.negotiate` доступен только аутентифицированным; собеседник
  резолвится через `users` (email или поиск), чужой контекст не отдаётся:
  каждый контекст собирается из памяти соответствующего userId.
- Ошибки AI-сервиса → `upstream_error`, переговоры не «выдумываются».

## Клиентские точки

| клиент | вызов |
| --- | --- |
| WS | `agent.ask` c `peers` (Аура сама предложит A2A) или `agent.negotiate {target, topic, duration_minutes, window_hours}` |
| Qt | ответ в чате (пузырь `agent_reply`), бейдж уведомлений |
| iOS | то же + вкладка «Уведомления» (`a2a.proposal`) |

E2E-покрытие: секция 3 прогона (`tools/e2e.py`) — «проведены переговоры
Agent-to-Agent», «A2A вернул слот или встречное предложение», «выбрано
место», публикация в чате.
