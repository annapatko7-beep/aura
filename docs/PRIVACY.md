# Приватность Aura

Коротко: ваши данные живут в вашей базе PostgreSQL; наружу уходят только
три класса запросов — к LLM/STT-провайдеру (если вы его включили), к Google
(только после явного подключения интеграции) и к вашему push-шлюзу.
SMS и телефон не используются вообще.

## Что хранится на сервере

| данные | где | в каком виде |
| --- | --- | --- |
| email, имя | `users` | открытым текстом (это логин) |
| пароль | `users.password_hash` | Argon2id, необратимо |
| коды подтверждения/сброса | `auth_tokens` | только SHA-256, одноразовые, TTL |
| refresh-токены | `refresh_tokens` | хэши, ротация при каждом обмене |
| TOTP-секрет 2FA | `two_factor_settings` | AES-256-GCM (ключ `AURA_2FA_KEY`) |
| резервные коды 2FA | `recovery_codes` | хэши, одноразовые |
| чаты и сообщения | `chats`/`messages` | открытым текстом (доступ только участникам) |
| память (факты, предпочтения) | `user_memory` | открытым текстом, строго по userId |
| настройки | `user_preferences` | JSONB |
| задачи | `tasks` | открытым текстом |
| токены Google | `integration_connections` | AES-256-GCM, клиенту не отдаются никогда |
| push-токены устройств | `push_devices` | сервером не сериализуются наружу |
| журнал безопасности | `audit_logs` | события без содержимого сообщений |

## Кто что видит

- **Другие пользователи** — только общие чаты и то, что вы сами отправили;
  память, задачи, настройки, уведомления изолированы по userId (покрыто
  тестами, TESTING.md).
- **AI Service** — получает контекст запроса (сообщение + релевантная
  память + календарь) и ничего не хранит между запросами
  (`AURA_MEMORY_BACKEND` — только если вы включили автономную память).
- **LLM-провайдер** (OpenAI-совместимый, если задан `OPENAI_API_KEY`) —
  видит текст запроса и присланный контекст. На `mock`-провайдере ничего
  не покидает ваш сервер.
- **Google** — только после вашего `integrations.begin` → consent;
  скоупы минимальны: `calendar.events.readonly`, `gmail.send`. Отзыв
  (`integrations.revoke`) отправляет токен в Google /revoke.
- **Push-шлюз** — получает APNs-конверт (заголовок/тело уведомления,
  токен устройства). Apple видит токен и payload. In-app уведомления
  не покидают сервер вовсе.

## Чего нет по принципу

- Нет SMS/телефонов — только email + пароль + TOTP 2FA + резервные коды.
- Нет аналитики, трекеров, рекламных SDK в клиентах.
- Нет «теневого» сбора: память пополняется из ваших сообщений и явных
  `memory.add`; каждое действие Ауры видно в чате и подтверждениях.
- LLM не имеет прямого доступа к базе и инструментам: сервер валидирует
  план модели и исполняет только разрешённое (`tool_permissions`),
  опасное — только после вашего подтверждения.

## Управление данными

- Отозвать сессию: `sessions.revoke` / `revokeAll` (мгновенно).
- Отозвать интеграцию: `integrations.revoke`.
- Отозвать push-устройство: `devices.push.revoke`.
- Удалить аккаунт: `DELETE FROM users WHERE id=…` каскадно удаляет
  сессии, токены, 2FA, доверенные устройства, память, настройки, задачи,
  отложенные действия, интеграции, уведомления и push-устройства
  (ON DELETE CASCADE). Осознанные исключения (SET NULL): журнал
  безопасности сохраняется с обнулённым user_id, отправитель сообщений
  в чатах становится NULL — история переписки собеседника не разрушается.
  Отдельной кнопки «удалить аккаунт» в UI пока нет — это известный
  пробел (запланирован, см. ROADMAP).

## Транспорт

Продакшен — только `wss://`/`https://` за TLS-терминирующим прокси
(ядро сознательно без TLS: терминирование — задача прокси). Токены
клиентов — в Keychain (iOS) и QSettings с доступом только текущего
пользователя ОС (desktop).
