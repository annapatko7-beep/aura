# Selfvoy — веб-клиент (браузер, Android, iOS, Windows/macOS)

Один код на React 19 + TypeScript + Vite, оболочки — Capacitor (телефоны) и Electron (десктоп).
Работает с настоящим сервером Selfvoy по тому же WebSocket-протоколу, что Qt/Android/iOS-клиенты
(`docs/PROTOCOL.md`). Встроенных демо-данных и фейкового входа нет.

| Платформа | Оболочка | Папка |
|---|---|---|
| Android | Capacitor 8 (WebView) | `android/` |
| iOS | Capacitor 8 (WKWebView) | `ios/` |
| Windows, macOS, Linux | Electron | `electron/` |
| Браузер | — | `dist/` |

## Запуск

```bash
cd web
npm install
cp .env.example .env     # по желанию: адрес сервера для сборки
npm run dev              # http://localhost:5173 (сервер Selfvoy — ws://127.0.0.1:9000)
npm test                 # vitest: адреса сервера, WebSocket-клиент, валидация, таймлайн переговоров
npm run build            # tsc + сборка с Content-Security-Policy

npm run android          # сборка + cap sync + Android Studio
npm run ios              # сборка + cap sync + Xcode
npm run desktop          # сборка + окно Electron
npm run dist:win         # установщик .exe
```

Сквозная проверка в браузере против запущенного стека (сервер с `SELFVOY_MAIL_DRIVER=dev`):

```bash
npx vite build && npx vite preview --port 4173 &
SELFVOY_UI_URL=http://localhost:4173 node scripts/ui-e2e.mjs /tmp/ui-shots
```

Сценарий: регистрация → код из письма → включение 2FA (QR, ключ, резервные коды) → выход →
неверный пароль/код → вход с TOTP → приватность ИИ → переговоры → диалог с Selfvoy → задачи →
новое устройство снова спрашивает 2FA → экран «Сервер Selfvoy не отвечает».

## Приглашение по ссылке

На странице «Переговоры» → «Пригласить по ссылке» Selfvoy подбирает свободные окна владельца и
выдаёт ссылку `<SELFVOY_PUBLIC_URL>/#/i/<токен>` для человека без Selfvoy (`invite.*`,
`docs/PROTOCOL.md`). Ссылка показывается один раз. Страница гостя `#/i/:token` открывается без
входа (и вне оболочки, если вход есть): слоты по дням в часовом поясе браузера, имя, email и
комментарий, «Подтвердить» / «Не получится», после выбора — файл `.ics` для календаря.
Если сервер не знает `SELFVOY_PUBLIC_URL`, ссылку собирает клиент (только на своём http(s)-домене);
в Electron, Capacitor и на localhost показывается токен с подсказкой.

## Страницы записи и рефералы

Раздел «Запись» (`#/booking`; на телефоне — карточка на «Переговорах») — постоянные ссылки
`<SELFVOY_PUBLIC_URL>/#/b/<slug>` (`booking.*`): название, длительность, на сколько дней вперёд,
лимит в день, запас до встречи, серия до 12 еженедельных встреч, выходные; пауза, правка,
удаление и список записей гостей с отменой. Страница гостя `#/b/:slug` — свободное время по дням
(сначала 4 дня, «Показать ещё дни»), имя, email, комментарий и число встреч серии; после записи —
`.ics` со всеми встречами и ссылка управления `#/m/:token` (показывается один раз): перенос
ближайшей встречи (до 3 раз) и отмена одной встречи или всех. «Настройки → Пригласить друзей» —
реферальный код и ссылка `#/signup?ref=<код>`, список приглашённых; регистрация по такой ссылке
передаёт `ref` в `auth.register` (код помнится до конца вкладки). Браузерный сценарий:
`node scripts/booking-ui-e2e.mjs` (нужны сервер с `SELFVOY_MAIL_DRIVER=dev` и AI-сервис).

## Адрес сервера

Порядок выбора (`src/net/config.ts`):

1. адрес, который пользователь ввёл сам («Адрес сервера» на экране входа или в Настройках →
   Приложение); если он задан, клиент подключается только к нему;
2. `VITE_SELFVOY_SERVER_URL` — вшивается при сборке (`.env` или переменная CI `SELFVOY_SERVER_URL`);
3. `VITE_SELFVOY_FALLBACK_URL` — запасной: если основной не отвечает, клиент переключается сам;
4. платформенный дефолт — только если адрес при сборке не задан (или это dev-сборка Vite):
   продакшн-сборка с `VITE_SELFVOY_SERVER_URL` никогда не уходит на `ws://127.0.0.1` / `ws://10.0.2.2`.

Смена адреса на другой сервер завершает вход на устройстве: токены и локальные ленты (диалог с
Selfvoy, переговоры) удаляются до подключения к новому серверу — токены одного сервера не уходят
на другой.

| Где запущен клиент | Адрес по умолчанию | Что указать |
|---|---|---|
| Android-эмулятор | `ws://10.0.2.2:9000` (это компьютер разработчика) | — |
| Настоящий телефон | — | IP компьютера в той же Wi-Fi сети: `192.168.x.x` → `ws://192.168.x.x:9000`, либо продакшн `wss://…` |
| Electron, браузер на localhost | `ws://127.0.0.1:9000` | — |
| Браузер на https-домене | `wss://<тот же хост>` | — |

Ввод нормализуется: `192.168.1.5` → `ws://192.168.1.5:9000`, `https://selfvoy.example.com` →
`wss://selfvoy.example.com`. Сервер слушает все интерфейсы (`SELFVOY_HOST=0.0.0.0`), для телефона
откройте порт 9000 в брандмауэре компьютера.

Соединение: таймаут подключения 8 с, переподключение с паузами 1–2–4–8–15 с, перебор адресов.
После каждого переподключения клиент сначала восстанавливает вход по токену (`auth.token`, при
истёкшем — `auth.refresh`) и только потом отправляет запросы экранов. Обновление refresh-токена
идёт под межвкладочной блокировкой (`navigator.locks`, `src/state/reauth.ts`): две вкладки не
тратят один одноразовый токен дважды. Пока связи нет, вместо
белого экрана — «Поиск соединения с сервером Selfvoy…» с кнопкой «Повторить» и сменой адреса.

## Сетевые политики

- **Android**: страница открыта как `https://localhost`, поэтому `ws://` в локальной сети —
  «смешанное содержимое». Разрешено `android.allowMixedContent` (`capacitor.config.ts`) и
  `usesCleartextTraffic` + `res/xml/network_security_config.xml` (доверие только системным CA).
  Для продакшна используйте `wss://`.
- **iOS**: `NSAllowsLocalNetworking` в `Info.plist` — открытый `ws://` только к локальной сети,
  остальное через TLS.
- **Electron и браузер**: сборка получает `Content-Security-Policy` (`vite.config.ts`): код и
  шрифты только свои, соединения `ws:`/`wss:`/`http(s):` (адрес сервера задаёт пользователь),
  картинки — свои, `data:` (QR, аватар) и `https:`. В dev-режиме политика не ставится.
  CORS к WebSocket не применяется; сервер Selfvoy не требует `Origin`.

## Безопасность

- Пароль нигде не хранится. Правила те же, что на сервере: от 8 символов (до 256 байт UTF-8),
  буквы и цифры.
- Токены (access JWT + refresh): в Electron — `safeStorage` ОС (Keychain / DPAPI / libsecret),
  файл `userData/secure.json`, права 0600; на Linux без keyring (или с запасным `basic_text`
  со встроенным ключом) шифрования нет, и экран «Приложение» об этом говорит. На телефонах и в
  браузере — `localStorage` WebView в песочнице приложения (слабее Keystore/Keychain на
  рутованных устройствах). Android-оболочка исключена из резервных копий и переноса данных
  (`allowBackup="false"`, `res/xml/data_extraction_rules.xml`).
- Выход удаляет токены и локальные ленты сразу, `auth.logout` — после, без ожидания сети.
- Electron: в окне открывается только `dist/index.html` (или dev-сервер `SELFVOY_DEV_URL` в
  неупакованном приложении); прочая навигация, в т. ч. перетащенный файл, блокируется, IPC
  хранилища отвечает только этой странице, из разрешений браузера — только микрофон.
- Id устройства для «доверенных устройств» 2FA — случайный, хранится рядом с токенами; если
  хранилища нет, id живёт до перезапуска и «Доверять устройству» не предлагается.
- 2FA — только TOTP (QR + ключ, 6 цифр), резервные коды XXXXX-XXXXX, доверенные устройства на
  90 дней. Без SMS.
- Опасные действия (бронь, письма) идут через подтверждение пользователя — решает сервер.

## Как устроено

| Папка | Что внутри |
|---|---|
| `src/net/` | `socket.ts` — WS-клиент (id ↔ ответ, таймауты, реконнект, события); `api.ts` — типизированные методы протокола; `config.ts` — адрес сервера; `secureStore.ts` — токены |
| `src/state/` | `session.tsx` — вход, регистрация, 2FA, восстановление пароля, refresh; `data.tsx` — задачи, чаты, уведомления, подтверждения, переговоры, живые события |
| `src/pages/` | Вход и регистрация, Главная, Selfvoy (диалог), Переговоры (форма, итог, таймлайн), Задачи, Контакты, Входящие, Настройки |
| `src/components/` | Оболочка (боковая панель / нижние вкладки), командная строка с голосом, экран соединения, общие элементы |
| `src/lib/` | Валидация форм, форматирование дат, шаги таймлайна переговоров, голос |
| `src/platform/` | Платформа (`data-platform` на `<html>`), нативные плагины, кнопка «Назад» на Android |
| `electron/` | Окно, внешние ссылки в браузер, IPC защищённого хранилища (`preload.cjs` → `window.selfvoySecure`) |

Стили — `src/styles/global.css`: токены `--bg #0b0c10`, `--surface #12141c`, рамки
`rgba(255,255,255,.08)`, шрифт Inter (встроен, работает без сети).

## Сборки в CI

`.github/workflows/build-web-demo.yml` («Build web client»): тесты, сборка, APK и установщик
Windows. Адрес сервера — переменные репозитория `SELFVOY_SERVER_URL` и `SELFVOY_FALLBACK_URL`
(Settings → Secrets and variables → Actions → Variables). Файлы: Artifacts прогона и релиз
«builds» (`Selfvoy-web.apk`, `Selfvoy-web-Setup.exe`).

Для публикации: Google Play — свой keystore и `./gradlew bundleRelease`; App Store — Apple
Developer Program; Windows/macOS — сертификаты подписи (`CSC_LINK`, `CSC_KEY_PASSWORD`).
Идентификатор приложения — `app.selfvoy.network`.
