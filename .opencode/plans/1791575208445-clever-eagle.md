# Редизайн Aura по макетам пользователя (Glassmorphism v3) — дизайн в приоритете

## Решения пользователя
- Область: **все платформы** (preview HTML → desktop QML → Android → iOS)
- Экраны: **все 8 из макетов** (Login, Register, Home, My Aura/Chat, Tasks, Contacts, Negotiations, Settings)
- **Home становится главным экраном после входа** (вместо чатов)
- Мокапы сохраняются в `docs/design-mockups/` как референс

## Контекст (что выяснено)
- Дизайн-система v2 «Dark Glassmorphism» уже есть и синхронизирована в 5 источниках:
  `client/qml/theme/AuraTheme.qml`, `preview/styles.css`, `client/styles/aura_theme.qss`,
  `android/.../ui/theme/Theme.kt`, токены iOS в `docs/DESIGN_SYSTEM.md`.
- В `TODO_PRODUCTION_READY.md:385-416` уже описан этот ре-дизайн (те же макеты) — план
  реализует и закрывает этот чеклист.
- Инфраструктурные блокеры v1.0 (Makefile, docker-compose, README, LICENSE) уже сделаны.
- Home-дашборда в клиентах нет. Desktop-рельс: Чаты/Задачи/Ждут/Пуши/Ещё — не как в макете.
- Протокол `agent.negotiate` на сервере есть (`docs/PROTOCOL.md:135`), в QML AppStore вызова нет
  (`client/src/appstore.cpp:689` — только `agent.ask`) → добавим тонкую обёртку, **без смены протокола**.

## Этап 3 — Desktop QML (главный клиент)
Файлы:
- **Новые**: `client/qml/HomePage.qml`, `client/qml/NegotiationsPage.qml`, `client/qml/ContactsPage.qml`
- **Правки**: `Main.qml`, `LoginPage.qml`, `DesktopShell.qml`, `ChatsPage.qml`, `ChatPage.qml`,
  `SettingsPage.qml`, `components/GlassButton.qml` (gradient-вариант), `components/TasksPanel.qml`,
  `components/ChatBubble.qml`, `components/VoicePanel.qml`, `components/GlassField.qml` (иконка-слот)
- `client/src/appstore.h/.cpp`: Q_INVOKABLE `negotiateAgent(target, topic, ...)` → `agent.negotiate`
  (переиспользует существующий sendRequest; протокол не меняется)

Работы:
1. **GlassButton**: вариант `gradient` (linear #7C6AFF→#A78BFA + glow-тень) — используется везде.
2. **GlassField**: слот под иконку (конверт/замок/глаз) слева, глаз-тумблер видимости пароля.
3. **LoginPage**: эмблема-лого (Canvas: кольцо + лучи + пульс glow), разделение потоков
   вход/регистрация на два визуальных состояния с полями как в макете; Google-кнопка —
   проверяет существующий OAuth-флоу сервера (dev-мок `AURA_E2E_GOOGLE_MOCK`), потоки
   verify/twofactor/forgot/reset сохраняются без изменений.
4. **HomePage (новый)**: приветствие по времени суток + `App.userName`; карточка статуса
   «Аура активна» (connected) со свечением; строка запроса → `agent.ask` (как в preview),
   круглая кнопка микрофона → существующий VoicePanel/voiceState; чипы быстрых действий
   (Plan a meeting / Check my schedule / …); Upcoming tasks ← `App.tasks`; Recent AI activity ←
   `App.notifications`/память. Адаптив: компактная раскладка тоже начинается с Home.
5. **DesktopShell**: рельс с логотипом и пунктами Home / My Aura / Negotiations / Tasks /
   Contacts / Settings; активный пункт — lilac-индикатор слева; бейджи подтверждений/уведомлений
   сохранить (иконкой на рельсе + счётчик в Home). Подтверждения/Пуши — из Home-карточек
   и/или вторичные иконки рельса (не терять барьер безопасности!).
6. **ChatPage/ChatBubble**: шапка с градиент-аватаром Ауры + «Online · Personal assistant»;
   индикатор «Aura is thinking…» (три пульсирующие точки) пока `App.busy`; чипы быстрых
   ответов под последним сообщением Ауры.
7. **TasksPanel**: точечные статусы (жёлтая/зелёная/фиолетовая), прогресс «до следующего
   события» (ближайший remindAt), недельная полоса дней, FAB «+» с формой создания
   (существующие `tasks.create/list/complete/delete`).
8. **ContactsPage (новый)**: список собеседников ← `App.chats` (email, online), аватар-сфера,
   детальная карточка справа (master-detail при ≥1120px, как чаты).
9. **NegotiationsPage (новый)**: форма запуска `agent.negotiate` (target/topic/duration/window)
   + карточка результата (accepted/slot/counter_slots/message) + таймлайн раундов из ответа;
   пустое состояние с объяснением лимита 5 раундов → эскалация.
10. **SettingsPage**: индикатор активной секции (lilac), карточки разрешений с тумблерами ←
    существующие `App.toolPermissions` (рендер динамический, без хардкода «Payments»).
11. **Main.qml фон**: глубже фиолетовые/маджента блобы + ambient-подсветка; сетку оставить.

## Этап 6 — Верификация (обязательно перед «готово»)
1. `python -m pytest` в `ai/` — не должно сломаться (не трогаем, но прогон)
2. qmlcachegen (PySide6) по всем `client/qml/**/*.qml` — синтаксис QML без GUI
3. CJK-скан по всем правленым файлам:
   `grep -nP '[\x{3040}-\x{30ff}\x{3400}-\x{4dbf}\x{4e00}-\x{9fff}]' <файлы>`
4. `make protocol-check` (протокол не менялся — должно быть зелёным)
5. Контраст новых текстов ≥ 4.5:1 (bg #16161A)
6. preview/index.html в браузере — визуальное сравнение с `docs/design-mockups/` экран за экраном
7. `TODO_PRODUCTION_READY.md` — отметить выполненные пункты редизайна
8. Сервер не трогаем → `make server-test/e2e` не требуются; если добавили `negotiateAgent` —
   проверить вручную против запущенного стека или в preview-моке

## Порядок выполнения (дизайн — главный приоритет)
Этап 0 → 1 (токены) → 2 (preview, визуальная сверка с макетами) → 3 (QML desktop) →
4 (Android) → 5 (iOS) → 6 (проверки). Каждый экран: preview → QML → mobile, чтобы
референс утверждался один раз.
